# 엔트리 터보 (비공식)

엔트리([playentry.org](https://playentry.org)) 작품의 블록을 자바스크립트로 바꿔서 **빠르게** 실행하는 크롬 확장입니다.
블록이 하는 일과 결과는 원래 엔트리와 같게 맞췄고, 작품 자체는 건드리지 않습니다.

> 엔트리 팀(커넥트재단)과 관계없는 **비공식** 확장입니다.

**[최신 버전 받기](https://github.com/Hawakiki/entry-turbo/releases/latest)** · [설치 방법](#설치) · [문제 알리기](https://github.com/Hawakiki/entry-turbo/issues/new/choose)

## 무엇이 달라지나요

| 기능                  | 하는 일                                                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 블록 컴파일           | 스크립트를 한 번 자바스크립트로 바꿔서 실행합니다. 블록의 결과와 기다리는 타이밍은 원래와 같습니다.                |
| 변수 표시 갱신 모으기 | 엔트리는 변수에 값을 넣을 때마다(숨긴 변수도) 무대 표시를 다시 계산합니다. 이걸 한 프레임에 한 번으로 모읍니다.    |
| 속도계(OSD)           | 무대 왼쪽 위에 FPS, 틱, 스크립트 시간, 그래프를 띄웁니다.                                                          |
| 부드럽게(보간)        | 기본은 꺼져 있습니다. 60Hz보다 빠른 모니터에서 움직임을 모니터 주사율로 그립니다. 작품이 도는 방식은 그대로입니다. |
| 재귀 한계 풀기(실험)  | 기본은 꺼져 있습니다. 함수가 자기 자신을 부르는 깊이를 1만 단계에서 100만 단계로 올립니다(엔트리는 수천 단계).     |

계산이 많은 작품일수록 효과가 큽니다. 그림이나 소리 위주의 작품은 차이가 작을 수 있습니다.

측정 예시 (공개 작품 [「진짜 리눅스 6.1」](https://playentry.org/project/6ab8a912e74f73da0867850c), 부스트 모드, 만든 사람의 PC 기준):

|                                    | 확장 없음 | 확장 켬 |
| ---------------------------------- | --------- | ------- |
| ▶ → 준비 완료                      | 143초     | 8.3초   |
| ▶ → 커널 기록이 끝나고 셸 프롬프트 | 189초     | 10.7초  |

## 설치

크롬 웹 스토어에는 올라가 있지 않아서, 파일을 받아 직접 넣습니다. 아래 과정은 처음 한 번만 하고, 새 버전은 [업데이트](#업데이트)처럼
덮어쓰면 됩니다.

1. **[최신 버전](https://github.com/Hawakiki/entry-turbo/releases/latest)** 페이지 아래 **Assets** 에서 `entry-turbo-v….zip` 을 받습니다.
2. 받은 zip의 압축을 풉니다. 나중에 업데이트할 때 같은 폴더를 쓰니, 지우지 않을 곳에 두세요.
3. 크롬 주소창에 `chrome://extensions` 를 입력합니다.
4. 오른쪽 위 **개발자 모드** 를 켭니다.
5. **압축해제된 확장 프로그램을 로드합니다** 를 누르고, 압축을 푼 폴더를 고릅니다.
6. 열어 둔 엔트리 탭이 있으면 새로고침합니다.

웨일(`whale://extensions`)과 엣지(`edge://extensions`)도 같은 방법으로 넣을 수 있습니다.

## 쓰는 법

설치하면 엔트리 작품 페이지와 만들기 화면에서 자동으로 켜집니다. 툴바의 확장 아이콘(퍼즐 모양 안에 있으면 고정해 두면 편합니다)을
누르면 팝업이 열립니다.

- **켜기 / 블록을 JS로 컴파일 / 변수 표시 갱신 모으기 / 재귀 한계 풀기**: 실행 중에 바꾸면 작품을 멈춘 뒤 다음 실행부터 적용됩니다.
  재귀 한계를 풀면 확장이 없는 사람에게는 같은 작품이 엔트리 한계에서 멈추니, 공개할 작품에는 조심해서 쓰세요.
- **속도계(OSD) 표시**, **부드럽게(보간)**: 바로 적용됩니다.
- **이 탭의 상태**: 컴파일된 스크립트 수와, 원래 방식으로 도는 스크립트가 있으면 그 이유를 보여 줍니다.

엔트리의 **부스트 모드** 와 같이 쓰면 계산이 많은 작품이 더 빨라집니다.

## 안전

- **권한**: 설정 저장(`storage`)과 playentry.org 주소뿐입니다. 다른 사이트에서는 동작하지 않습니다.
- **보내는 것**: 없습니다. 팝업을 열 때 GitHub에 "최신 버전 번호"만 물어봅니다(새 버전 알림용, 6시간에 한 번).
- **코드**: 이 저장소에 전부 공개돼 있고, 압축(난독화)하지 않았습니다. 확장이 쓰는 파일은 `manifest.json`, `src/`, `popup/` 입니다.
- **서명**: 릴리스 태그와 커밋은 GPG로 서명돼 있습니다(GitHub에서 **Verified** 로 보입니다).
- **파일 확인**: 릴리스 zip은 GitHub Actions가 그 태그의 코드로 만들었고, 출처 증명과 SHA-256이 붙어 있습니다.
  같은 코드로 직접 빌드해도 같은 해시가 나옵니다.

받은 파일을 직접 확인해 보려면(선택):

```bash
# 윈도우: 릴리스에 적힌 SHA-256 과 같은지
certutil -hashfile entry-turbo-v<버전>.zip SHA256
# GitHub CLI: 이 저장소의 Actions 가 만든 파일인지
gh attestation verify entry-turbo-v<버전>.zip -R Hawakiki/entry-turbo
```

## 알아 둘 점

- 확장을 **설치한 사람의 화면에서만** 빨라집니다. 작품을 보는 다른 사람에게는 영향이 없습니다.
- 일부 블록은 원래 방식으로 돕니다: AI·날씨·번역 같은 온라인 블록, 기다리는 동작이 든 값 반환 함수 등.
- 엔트리가 업데이트되면, 확인하지 못한 부분은 자동으로 원래 방식으로 돌아갑니다(틀리지 않고 느려지기만 합니다).
- 작품이 이상하게 움직이면 팝업에서 스위치를 하나씩 꺼 보고, [이슈](https://github.com/Hawakiki/entry-turbo/issues/new/choose)로 알려 주세요.
  어떤 스위치를 끄면 괜찮아지는지 알려 주시면 원인을 찾기 쉽습니다.

## 업데이트

새 버전이 나오면 팝업 위쪽에 알림이 뜹니다.

1. 새 zip을 받아 **처음 설치한 폴더에 덮어쓰기** 로 압축을 풉니다.
2. `chrome://extensions` 에서 엔트리 터보의 **새로고침** 버튼(↻)을 누릅니다.

설정은 그대로 남습니다.

## 개발

```bash
pnpm install
pnpm lint          # 고치기: pnpm lint:fix
pnpm build         # dist/ 에 확장 파일만 모은다
pnpm release       # dist/ → release/entry-turbo-v<버전>.zip + .sha256 (같은 커밋이면 같은 해시)
```

크롬에 넣기(배포 없이): `chrome://extensions` → 개발자 모드 → "압축해제된 확장 프로그램을 로드합니다" → `dist/`.
코드를 고치면 `pnpm build` → 확장 카드의 새로고침 → 작품 탭 새로고침.

릴리스: `manifest.json` 의 `version` 을 올려 커밋 → `git tag v<버전>` 푸시 → Actions(`release.yml`)가 zip·해시를 만들어 출처 증명과 함께
**초안** 릴리스에 붙인다 → 설명을 쓰고 게시. 푸시·PR 마다 `ci.yml` 이 린트와 빌드를 돌린다.
팝업은 열릴 때 GitHub API 로 최신 릴리스 번호를 확인해 새 버전을 알린다(6시간마다 한 번). `manifest.json` 의 `key` 는
확장 ID 를 고정한다(어느 폴더에 풀어도 같은 확장).

시험판(rc): 크롬의 `version` 은 숫자만 받으므로 rc 번호를 넷째 자리에 두고, 보이는 이름은 `version_name` 에 둔다
(규칙은 `scripts/version.js`, 어긋나면 빌드가 멈춘다).

| 판         | `version` | `version_name` | 태그          | GitHub 릴리스 |
| ---------- | --------- | -------------- | ------------- | ------------- |
| 0.3.0 rc 1 | `0.3.0.1` | `0.3.0-rc.1`   | `v0.3.0-rc.1` | 프리릴리스    |
| 0.3.0 정식 | `0.3.0`   | (없음)         | `v0.3.0`      | 일반          |

rc 태그는 `develop` 에서, 정식은 `version_name` 을 지우고 `main` 에 머지한 뒤 `main` 에서. 정식 사용자는 `releases/latest`
(프리릴리스 제외)만 보므로 rc 알림을 받지 않고, rc 사용자는 더 새 rc 와 정식을 모두 알림받는다(`0.3.0-rc.N < 0.3.0`).

### 검증

entry-test(공개하지 않은 별도 도구 모음: CDP·블록 DSL)를 쓴다. 이 저장소 옆 폴더 `../entry-test`, 또는 `ENTRY_TEST` 환경 변수.

```bash
node bench/run.js                      # 오프라인 에디터 A/B: 결과·틱 수 대조 (Entry.exe 재시작)
node bench/ui-check.js                 # UI 블록(이동·말하기·기다리기·신호·복제본): 무대 상태 대조
node bench/func-check.js               # 함수(매개변수·지역변수·값 함수·재귀): 상태·틱 수 대조
node bench/smooth-check.js             # 보간: 그리는 횟수·틱 사이 위치·끝 상태 대조
node bench/compile-check.js 작품.ent    # 실행 없이 전부 컴파일해 보기 (Entry.exe 재시작)
node bench/web-linux.js                # 웹 공개작(진짜 리눅스)에 확장 스크립트를 넣고/빼고 (디버깅 크롬 9333)
node bench/web-shot.js [작품 id] [--boost] [--zoom]   # 웹 작품에 확장을 넣고 ▶ 뒤 플레이어 캡처 (OSD·무대 눈으로 확인)
node bench/fingerprints.js             # 새 엔트리 빌드의 코드를 읽고 규칙을 확인한 뒤 KNOWN 갱신
node bench/dump-blocks.js              # 웹·오프라인의 블록 스키마와 func 원문 → ref/blocks-*.json (블록 분류 재료, Entry.exe 재시작)
node bench/profile.js                  # 변수·리스트 쓰기 단가, 표시 끈 반복 벤치 (bench/run.js 가 띄운 에디터에 붙음)
```

linux-real 비트 대조: `node linux-real/verify-app.js --turbo <이 폴더>/src/turbo.js [--boost]` (entry-test 에서).
